# Latency work — 4 November 2026

Host: Intel Alder Lake, VA-API low-power H.264, 1920×1200. Tablet: Samsung
SM-X620 (90 Hz panel, Exynos decoder), USB 2.0 cable.

## How it was measured

The companion now stamps pongs with its monotonic clock, so the host estimates
the clock offset from the fastest round trip in each 10 s window (error ≤ half
that RTT, typically 1–2 ms). With it the host reports two one-way figures in
its debug "health sample" log and the Statistics row:

- **screen** — capture on the host to the frame being released for display by
  the tablet decoder. Excludes the panel's own scan-out.
- **touch** — the tablet's input sample time (`MotionEvent` event time) to the
  host reading it.

`scratch/latency-run.py NAME` restarts the host with debug logs, shows a moving
test pattern full-screen on the tablet, injects `adb input` swipes and writes
a summary. Swipes are injected, not physical touches. Runs of the same build
vary by about ±1.5 ms.

## Results (medians)

| Step | screen | touch |
| --- | ---: | ---: |
| Starting point (60 fps, ADB) | 30.5 ms (p90 40) | 12.1 ms |
| 1. Stream at the panel rate (90 Hz) | 24.0 ms (p90 30) | 9.5 ms |
| 2. Unbuffered touch/stylus dispatch | 24.7 ms | 4.7 ms |
| 4. USB accessory instead of ADB | 24.6–26.4 ms | 2.2 ms |
| 8. Pacer slack | **19.3–19.6 ms (p90 22)** | 2.3 ms |

Round trip on the control channel fell from ~2.5 ms (ADB) to ~1 ms (AOA).

## Changes

1. **Frame rate 0 = match the tablet** (new default). Android no longer drops a
   90 Hz panel to 60 Hz for us; capture, encode cadence and vsync all shorten.
2. **`requestUnbufferedDispatch`** on the window: touch and pen samples are no
   longer batched to one per vsync. ~110 events/s reach the host instead of ~84.
3. **Rate-control buffer capped at two frames.** Works on x264 (largest frame
   175 KB → 60 KB) and is set for NVENC. Intel's VA driver ignores `cpb-size`
   on both VA encoders; verified outside the app, frame sizes are identical.
4. **USB accessory:** video frames are split into 16 KiB pieces
   (`flags::FRAGMENT`, protocol v2) so control frames — cursor moves, pings —
   wait at most one piece; the writer lock is a condition variable instead of
   a spinning yield loop. Splitting showed no measurable throughput cost.
   Also fixed: the companion crashed on `USB_ACCESSORY_DETACHED`
   (`UsbAccessory.equals` reads the serial, which throws once permission is
   gone), and a host restart left a tablet stuck in accessory mode; an explicit
   Accessory selection now resumes on USB before trying ADB.
5. **`num-slices=4` removed.** One vs four slices measured the same (frames are
   sent whole, so slices cannot overlap the transfer) and slices cost quality.
6. **Instant pen ink** (companion setting, on by default): a 150 ms fading
   trail drawn locally under the pen. Verified on the tablet by screenshot.
7. **x264 intra refresh.** Decodes correctly on the tablet. Not available on
   VA-API, and NVENC was not testable here, so it is not set there. The short
   runs saw too few periodic keyframes to show the spike reduction.
8. **Pacer slack.** Frames waited 5.2 ms on average (max 11 ms, one period at
   90 Hz) because capture and the pacer drift out of phase. Allowing delivery a
   quarter period early cut the wait to 0.17 ms; PTS stay a full period apart
   so the drop-only `videorate` never discards a frame.
